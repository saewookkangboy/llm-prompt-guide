# ADR-0001. 하네스를 6개 레이어로 분리한다

- 상태: 채택
- 날짜: 2026-08-12

## 맥락

초기 프로토타입은 단일 파일에 프롬프트·툴 호출·검증이 섞여 있었다.
프롬프트 한 줄을 고치면 무엇이 영향받는지 알 수 없었고, 툴을 단독으로
테스트할 수 없었으며, 모델 교체 시 전부를 다시 검증해야 했다.

## 결정

컨텍스트 / 프롬프트 / 툴 / 오케스트레이션 / 가드레일 / 관측 6개로 나누고,
의존 방향을 단방향으로 고정한다 (`docs/01-architecture.md`).

## 결과

**좋아지는 것**: 툴 계약 테스트 가능, 프롬프트 변경 영향 범위가 파일 단위로
드러남, 모델 교체가 `config/models.yaml` 수정으로 좁혀짐.

**나빠지는 것**: 파일 수가 늘고, 기능 하나 추가에 3~4개 디렉터리를 건드린다.
소규모 프로토타입에는 과한 구조다 — 실험 단계에서는 `experiments/`에서 단일
파일로 시작하고, 승격할 때 레이어로 쪼갠다.

## 대안

- 프레임워크 기본 구조 채택 — 프레임워크 교체 시 전부 재작성 위험으로 기각
- 레이어 없이 기능별 분리 — 가드레일·관측이 기능마다 중복되어 기각
