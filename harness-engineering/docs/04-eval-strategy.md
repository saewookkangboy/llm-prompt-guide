# 04. 평가 전략

## 3종 데이터셋

| 셋 | 목적 | 규모 | 갱신 |
|---|---|---|---|
| `golden/` | 대표 업무의 정답 기준 | 120건 | 분기 |
| `regression/` | 과거에 깨졌던 케이스 | 누적 | 실패 발생 즉시 |
| `adversarial/` | 프롬프트 인젝션·범위 이탈·PII 유도 | 60건 | 월 |

골든셋은 사람이 만든다. 모델이 생성한 정답으로 모델을 평가하면
그 모델의 편향을 그대로 통과시킨다.

## 3단 판정

1. **결정적 검사** — 스키마 유효성, 필수 필드, 금칙어, 길이. 실패 시 즉시 탈락.
2. **LLM 저지** — 루브릭 기반 채점(`evals/rubrics/`). 저지 모델은 대상 모델과 다른 것을 쓴다.
3. **사람 표본 검토** — 주당 20건. 저지 점수와 사람 판정의 상관이 0.7 아래면
   루브릭을 고친다. 저지를 믿기 전에 저지를 평가한다.

## 릴리스 게이트

```
smoke        PR마다      골든셋 20건    통과율 ≥ 85%
release-gate 배포 전     전체 3종       골든 ≥ 90% · 회귀 100% · 적대적 ≥ 95%
```

회귀 스위트는 **100%가 아니면 배포하지 않는다.** 한 번 고친 버그가 다시
나오는 것은 새 버그보다 신뢰를 크게 깎는다.

## 하지 말 것

- 평가셋을 프롬프트 예시로 재사용 — 시험 문제를 교재에 넣는 것과 같다
- 점수 하나로 요약 — 실패 **유형별** 분포를 본다
- 통과율만 보고 비용·지연 무시 — 세 지표는 항상 같이 본다
