# 03. 루프 엔지니어링

하네스가 구조라면, 루프는 그 구조를 개선하는 사이클이다.

## 두 종류의 루프

### 런타임 루프 (실행 중)
```
계획 → 실행 → 자기평가 → (미달이면 재계획)
```
- 종료 조건: 자기평가 통과 · 최대 6회 · 예산 초과 중 하나
- 자기평가는 별도 프롬프트(`prompts/task/self_critique.md`)로 분리한다.
  같은 프롬프트 안에서 "잘 했는지 확인해"라고 덧붙이면 모델은 거의 항상 통과시킨다.

### 개선 루프 (실행 밖, 주 단위)
```
트레이스 수집 → 실패 유형 분류 → 가설 → 실험 → 평가 → 승격 또는 폐기
```

## 개선 루프 운영 규칙

1. **실패에서 시작한다** — 아이디어가 아니라 지난주 트레이스의 실패 케이스에서.
2. **한 번에 하나만 바꾼다** — 프롬프트와 라우팅을 같이 고치면 무엇이 효과였는지 모른다.
3. **실패 케이스는 즉시 평가셋으로 간다** — `evals/datasets/regression/`.
   고친 뒤에 다시 깨지는 걸 막는 유일한 방법이다.
4. **폐기도 기록한다** — `experiments/`에 실패한 가설이 남아야 6개월 뒤에
   같은 실험을 반복하지 않는다.

## 실험 1건의 최소 형식

`experiments/templates/experiment-brief.md` 참조. 가설·측정 지표·기준선·
판정 기준을 **실험 전에** 적는다. 결과를 본 뒤 기준을 정하면 모든 실험이 성공한다.
