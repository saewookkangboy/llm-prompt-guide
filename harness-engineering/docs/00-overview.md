# 00. 프로젝트 개요

## 무엇을 만드는가

ATLAS는 마케팅 조직의 반복 업무(리서치 → 전략 → 카피 → 검수)를 에이전트로
자동화하는 가상 프로젝트다. 다만 이 저장소의 관심사는 "에이전트가 무엇을 하는가"가
아니라 **"에이전트를 어떻게 감싸는가"** — 즉 하네스다.

## 왜 하네스인가

모델 교체는 하루면 끝난다. 하지만 컨텍스트 조립 방식, 툴 권한 경계, 실패 시
복구 절차, 품질 측정 기준은 조직이 축적해야 하는 자산이다. 모델이 바뀌어도
하네스는 남는다.

```
[ 사용자 요청 ]
      │
      ▼
┌─────────────────────────────────────────┐
│  가드레일 (입력)                          │  ← 유해·PII·범위 이탈 차단
├─────────────────────────────────────────┤
│  컨텍스트 조립                            │  ← 검색 + 메모리 + 토큰 예산
├─────────────────────────────────────────┤
│  오케스트레이션 루프                       │  ← 라우팅 → 실행 → 자기평가 → 반복
│     ├─ 프롬프트 (버전 고정)               │
│     └─ 툴 (권한 검사 후 호출)              │
├─────────────────────────────────────────┤
│  가드레일 (출력)                          │  ← 스키마·사실성·톤 검증
├─────────────────────────────────────────┤
│  관측                                    │  ← 트레이스·비용·지연 기록
└─────────────────────────────────────────┘
      │
      ▼
[ 결과 + 트레이스 ID ]
```

## 성공 기준

| 지표 | 기준선 | 목표 |
|---|---|---|
| 골든셋 통과율 | 72% | 90% |
| 재작업률(사람이 다시 손댄 비율) | 45% | 15% |
| 건당 비용 | $1.80 | $0.60 |
| p95 지연 | 95s | 40s |

지표가 없으면 개선했는지 알 수 없다. 모든 실험은 위 네 개 중 하나를 겨냥한다.

## 범위 밖

- 모델 파인튜닝 — 하네스로 먼저 한계까지 간 뒤에 논의한다
- 자체 벡터 DB 운영 — 관리형 서비스 사용
- 프론트엔드 — 별도 저장소
