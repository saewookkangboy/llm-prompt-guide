# 02. 컨텍스트 엔지니어링

## 문제

컨텍스트 윈도가 커졌다고 다 넣으면 되는 게 아니다. 관련 없는 문서가 늘수록
모델은 중간 정보를 놓치고(lost-in-the-middle), 비용은 선형으로 늘며,
어떤 근거로 답했는지 추적이 불가능해진다.

## 토큰 예산 배분 (기본값)

| 구획 | 비중 | 초과 시 |
|---|---|---|
| 시스템 프롬프트 | 고정 | 절대 자르지 않음 |
| 툴 스키마 | 고정 | 워크플로에 필요한 툴만 로드 |
| 검색 문서 | 45% | 랭킹 하위부터 제거 |
| 대화·스크래치패드 | 30% | 오래된 턴부터 요약 |
| 메모리 | 15% | 요약본으로 교체 |
| 출력 여유분 | 10% | 확보 실패 시 실행 중단 |

`harness/context/budget.py`가 이 표의 단일 구현체다.

## 3계층 메모리

1. **작업 메모리** — 현재 실행 내 스크래치패드. 실행 종료 시 폐기.
2. **세션 메모리** — 사용자 세션 단위 요약. TTL 24시간.
3. **조직 메모리** — 브랜드 가이드·과거 캠페인 결과. 큐레이션된 것만 승격.

3계층은 자동 승격하지 않는다. 사람이 검토한 것만 조직 메모리로 올린다 —
잘못된 사실이 조직 메모리에 들어가면 모든 실행이 오염된다.

## 검색 규칙

- 최대 8개 청크, 유사도 임계값 미달은 개수 미달이어도 넣지 않는다
- 모든 청크는 출처 ID를 달고 들어간다 — 출처 없는 근거는 검증 불가
- 검색 결과 0건은 "빈 컨텍스트로 진행"이 아니라 **명시적 실패**다
