# ATLAS — 마케팅 에이전트 하네스

> 가상 프로젝트. LLM 프롬프트 가이드에서 다룬 **하네스 엔지니어링 / 루프 엔지니어링**
> 개념을 실제 코드베이스 구조로 옮긴 참조 스캐폴드입니다.

## 전제

모델은 부품이고, 성과를 만드는 것은 그 모델을 감싼 **하네스**다.
같은 모델을 써도 컨텍스트 조립·툴 권한·가드레일·평가 루프의 설계 품질에 따라
결과가 갈린다. 이 저장소는 그 하네스를 "문서"가 아니라 **버전 관리되는 자산**으로
다루기 위한 폴더 구조를 정의한다.

## 6개 레이어

| 레이어 | 위치 | 질문 |
|---|---|---|
| 컨텍스트 | `harness/context/` | 모델에게 **무엇을** 보여줄 것인가 |
| 프롬프트 | `harness/prompts/` | **어떻게** 지시할 것인가 (버전 관리 대상) |
| 툴 | `harness/tools/` | 무엇을 **할 수** 있게 할 것인가 |
| 오케스트레이션 | `harness/orchestration/` | 어떤 **순서·루프**로 돌릴 것인가 |
| 가드레일 | `harness/guardrails/` | 무엇을 **막을** 것인가 |
| 관측 | `harness/observability/` | 무슨 일이 **일어났는지** 어떻게 아는가 |

평가(`evals/`)는 레이어가 아니라 이 여섯 개 전부에 걸린 **릴리스 게이트**다.

## 폴더 구조

```
harness-engineering/
├── docs/            설계 문서 · ADR · 다이어그램
├── harness/         런타임 코드 (6개 레이어)
│   ├── context/         컨텍스트 조립 · 검색 · 메모리 · 토큰 예산
│   ├── prompts/         시스템/태스크 프롬프트 + 버전 레지스트리
│   ├── tools/           툴 스키마 · 어댑터 · 권한 정책
│   ├── orchestration/   그래프 · 라우터 · 루프 · 워크플로 정의
│   ├── guardrails/      입력 필터 · 출력 검증 · 정책
│   ├── observability/   트레이싱 · 메트릭 · 비용
│   └── config/          모델·환경 설정
├── evals/           골든셋 · 루브릭 · 저지 · 스위트 · 리포트
├── experiments/     루프 엔지니어링 실험 기록 (가설 → 결과)
├── runbooks/        장애·회귀 대응 절차
├── ops/             CI · 컨테이너 · 대시보드
├── data/            원본 · 가공 데이터 · 테스트 픽스처
├── scripts/         평가 실행 · 트레이스 리플레이 · 프롬프트 승격
└── tests/           unit · integration · contract
```

각 디렉터리의 `README.md`에 **무엇을 넣고 무엇을 넣지 않는지**가 적혀 있다.
새 파일을 놓을 자리가 헷갈리면 그 문서가 기준이다.

## 시작하기

```bash
cp .env.example .env
make install        # 의존성 설치
make eval-smoke     # 골든셋 20건으로 스모크 평가
make trace          # 최근 실행 트레이스 열기
```

## 원칙 4가지

1. **프롬프트는 코드다** — 인라인 문자열 금지. `harness/prompts/`에 파일로 두고 레지스트리로 버전을 고정한다.
2. **평가 없는 변경은 머지하지 않는다** — 프롬프트 한 줄을 고쳐도 `evals/suites/`가 돌아야 한다.
3. **툴 권한은 기본 거부** — `harness/tools/policy.yaml`에 명시된 것만 허용한다.
4. **모든 실행은 트레이스를 남긴다** — 재현 불가능한 실패는 디버깅할 수 없다.
