# orchestration/ — 루프와 워크플로

**넣는 것**: 라우팅, 상태 전이, 루프 종료 조건, 워크플로 조립
**넣지 않는 것**: HTTP 직접 호출(어댑터에 위임), 프롬프트 텍스트

| 파일 | 책임 |
|---|---|
| `state.py` | 실행 상태 정의 — **상태는 여기서만 정의한다** |
| `router.py` | 요청을 워크플로·모델로 라우팅 |
| `loop.py` | 계획→실행→자기평가 루프와 종료 조건 |
| `graph.py` | 워크플로 YAML을 실행 가능한 그래프로 조립 |
| `workflows/` | 단계 정의 (YAML) |

## 루프 종료 조건 (반드시 셋 다 구현)

1. 성공 — 자기평가 통과
2. 최대 반복 — 기본 6회
3. 예산 초과 — 토큰 또는 비용

셋 중 하나라도 빠지면 무한 루프이거나 조용한 실패가 된다. `halt_reason`을
남기지 않는 종료는 버그로 취급한다.

## 워크플로를 코드가 아니라 YAML로 두는 이유

단계 순서 변경은 가장 잦은 실험이다. 코드에 있으면 변경마다 배포가 필요하고,
어떤 순서로 돌렸을 때 점수가 얼마였는지 실험 기록과 연결하기 어렵다.
