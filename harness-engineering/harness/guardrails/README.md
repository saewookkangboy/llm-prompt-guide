# guardrails/ — 차단과 검증

**넣는 것**: 입력 필터, 출력 검증, 정책 평가
**넣지 않는 것**: 조용한 수정. 차단하거나 통과시키되, 결과는 반드시 트레이스에 남긴다.

| 파일 | 지점 |
|---|---|
| `input_filters.py` | 사용자 입력 (PII·인젝션·범위 이탈) |
| `output_validators.py` | 모델 출력 (스키마·근거·금칙·톤) |
| `policies/` | 데이터로 관리하는 규칙 |

## 원칙

"알아서 정리해주는" 가드레일은 문제를 숨겨 개선 루프를 굶긴다.
개입했으면 사용자에게 보이고 기록한다.

## 인젝션 방어는 이중으로

프롬프트(`partials/guardrail_block.md`)와 출력 검사 양쪽에서 막는다.
프롬프트 방어만으로는 부족하다는 전제로 설계한다.

## 새 규칙을 추가할 때

`evals/datasets/adversarial/`에 통과해야 할 케이스를 먼저 추가하고 규칙을 짠다.
규칙을 먼저 짜면 그 규칙이 막는 것만 테스트하게 된다.
