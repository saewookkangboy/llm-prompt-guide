# 근거 없는 출력 보고

## 증상

사용자 또는 검수자가 사실과 다른 수치·주장을 보고. 외부 발행된 경우 최우선.

## 즉시 조치

1. 외부에 나갔다면 발행 중단·회수를 먼저 한다. 원인 조사는 그 다음이다.
2. 해당 실행의 트레이스를 확보한다
   ```bash
   python scripts/replay_trace.py --run-id <run_id> --show sources,evicted,prompt_versions
   ```

## 원인 확인 체크리스트

- [ ] 검색 결과가 0건이었는가 → `fail_on_empty_retrieval`이 꺼져 있었는지 확인
- [ ] 근거가 절삭됐는가 → `evicted` 목록에 해당 청크가 있는지 확인
- [ ] 출력에 `sources`가 비어 있었는가 → 출력 검증이 왜 통과시켰는지 확인
- [ ] 프롬프트 버전이 무엇이었는가 → 최근 변경과 대조

가장 흔한 순서는 **절삭 → 근거 소실 → 모델이 빈칸을 채움**이다.
컨텍스트를 늘리는 것이 답이 아니라, 절삭 시 근거를 우선 보존하는 것이 답이다.

## 복구

`fail_on_empty_retrieval`과 출력 검증의 근거 존재 검사를 다시 켠다.
검사를 우회한 경로가 있었다면 그 경로를 막는다.

## 사후 조치

- 회귀 케이스 추가 (원인·수정 PR 기재)
- 같은 유형이 과거에 있었는지 `regression/` 검색 — 있었다면 왜 재발했는지 확인
