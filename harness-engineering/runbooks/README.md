# runbooks/ — 대응 절차

새벽 3시에 호출된 사람이 읽는 문서다. 배경 설명이 아니라 **순서대로 실행할
명령**을 쓴다. 각 러너북은 같은 구조를 따른다.

증상 → 즉시 조치 → 원인 확인 → 복구 → 사후 조치

## 목록

| 파일 | 언제 |
|---|---|
| `prompt-rollback.md` | 프롬프트 배포 후 품질 급락 |
| `cost-spike.md` | 비용이 임계를 넘음 |
| `hallucination-report.md` | 근거 없는 출력이 외부에 나감 |
| `tool-outage.md` | 외부 API 장애 |

## 사후 조치는 예외 없이 하나로 끝난다

**재현 케이스를 `evals/datasets/regression/`에 추가한다.**
이것을 하지 않으면 같은 장애가 다시 온다.
