# tests/

```
unit/         순수 로직 (예산 배분, 상태 전이, 정책 평가)
contract/     스키마 ↔ 어댑터 ↔ policy 일치 검증
integration/  워크플로 종단 실행 (픽스처 기반, 실제 모델 호출 없음)
```

## 모델 호출은 테스트가 아니다

모델 출력의 품질은 `evals/`가 본다. 여기서는 **하네스가 규칙대로 동작하는지**만
본다. 예: 예산 초과 시 정말 멈추는가, 정책에 없는 툴이 정말 거부되는가.

이 구분이 흐려지면 테스트는 느리고 불안정해지고, 결국 아무도 돌리지 않는다.

## contract 테스트가 잡는 것

- 스키마에 있는데 어댑터에 없는 파라미터 (그 반대도)
- `policy.yaml`에 등록되지 않은 스키마 파일
- 스키마의 제약과 `policy.yaml`의 `constraints` 불일치
- 부작용 있는 툴에 승인 요건이 빠진 경우
